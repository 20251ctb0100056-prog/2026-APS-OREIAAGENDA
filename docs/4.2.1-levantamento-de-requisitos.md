# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do PetAgenda foram definidos com base no problema apresentado pelo cliente Luiz Carlo, responsável pelo balcão do pet shop. Foram consideradas as necessidades de organizar os horários dos atendimentos, cadastrar os animais e seus responsáveis e evitar conflitos nos agendamentos.

❓ **A confirmar com o cliente:** verificar se os agendamentos precisam registrar o funcionário responsável, se os cancelamentos devem ter um motivo e se os serviços possuem durações diferentes.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso organizar melhor os horários dos atendimentos." (Cliente) | Necessidade | Organizar os agendamentos e facilitar a consulta dos horários. |
| F2 | "Quero cadastrar os animais e seus responsáveis." (Cliente) | Solução | Manter os dados dos pets e de seus responsáveis organizados. |
| F3 | "Não quero marcar dois atendimentos para o mesmo horário." (Cliente) | Necessidade | Evitar conflitos entre os agendamentos. |
| F4 | "Preciso consultar os horários de cada dia." (Cliente) | Solução | Encontrar rapidamente os atendimentos marcados para uma data. |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **atendente do balcão**, quero **cadastrar os pets e seus responsáveis**, para **manter os dados dos clientes organizados**. | F2 |
| HU02 | Como **atendente do balcão**, quero **registrar agendamentos**, para **organizar os atendimentos do pet shop**. | F1 |
| HU03 | Como **atendente do balcão**, quero **consultar os agendamentos por data**, para **saber quais atendimentos estão programados**. | F4 |
| HU04 | Como **atendente do balcão**, quero **cancelar agendamentos**, para **manter a agenda atualizada quando houver mudanças**. | F1 |
| HU05 | Como **atendente do balcão**, quero **verificar a disponibilidade de horários**, para **evitar conflitos entre os atendimentos**. | F3 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar pet | O sistema deve cadastrar pets e seus dados. | HU01 |
| RF02 | Cadastrar responsável | O sistema deve cadastrar os responsáveis pelos pets. | HU01 |
| RF03 | Registrar agendamento | O sistema deve registrar agendamentos de serviços. | HU02 |
| RF04 | Consultar agendamentos | O sistema deve consultar os agendamentos por data. | HU03 |
| RF05 | Cancelar agendamento | O sistema deve cancelar agendamentos registrados. | HU04 |
| RF06 | Verificar disponibilidade | O sistema deve verificar a disponibilidade do horário solicitado. | HU05 |
| RF07 | Cadastrar serviço | O sistema deve cadastrar os serviços oferecidos pelo pet shop. | HU02 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade | O sistema deve apresentar informações de forma simples e organizada, facilitando a consulta dos agendamentos pelo atendente. | Características da 4.1 |
| RNF02 | Integridade | O sistema deve impedir o registro de agendamentos conflitantes para o mesmo horário de atendimento. | F3 |
| RNF03 | Desempenho | O sistema deve apresentar os agendamentos de uma data em até 3 segundos em condições normais de uso. | Necessidade de consulta rápida |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| Cadastrar pets e responsáveis. | RF01, RF02 |
| Cadastrar os serviços oferecidos. | RF07 |
| Registrar agendamentos. | RF03 |
| Consultar agendamentos por data e horário. | RF04 |
| Cancelar agendamentos. | RF05 |
| Evitar conflitos de horários. | RF06, RNF02 |

Todas as histórias de usuário possuem requisitos funcionais relacionados, e todos os requisitos apresentam uma origem identificada. A conferência verificou se as funções previstas na descrição do projeto estão representadas nesta seção. O requisito de integridade reforça a necessidade de evitar conflitos de horários, enquanto os requisitos não funcionais definem condições de facilidade de uso e rapidez nas consultas.
