# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do PetAgenda foram pensados a partir das necessidades do cliente Luiz Carlo, que trabalha no balcão do pet shop. A ideia é facilitar a organização dos horários, guardar os dados dos animais e de seus donos e evitar que dois atendimentos sejam marcados para o mesmo horário.

❓ **A confirmar com o cliente:** saber se será necessário colocar o nome do funcionário responsável pelo atendimento, informar o motivo de um cancelamento e definir um tempo diferente para cada serviço.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso organizar melhor os horários do pet shop." (Cliente) | Necessidade | Deixar os horários dos atendimentos organizados. |
| F2 | "Quero guardar os dados dos animais e dos donos." (Cliente) | Solução | Ter os dados dos pets e dos responsáveis em um só lugar. |
| F3 | "Não quero marcar dois animais no mesmo horário." (Cliente) | Necessidade | Evitar que dois atendimentos sejam marcados no mesmo horário. |
| F4 | "Quero ver quais atendimentos estão marcados para o dia." (Cliente) | Solução | Conseguir consultar os horários sem se perder na agenda. |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **atendente**, quero **cadastrar os animais e seus donos**, para **encontrar seus dados quando precisar**. | F2 |
| HU02 | Como **atendente**, quero **marcar os atendimentos**, para **organizar os horários do pet shop**. | F1 |
| HU03 | Como **atendente**, quero **consultar os horários do dia**, para **saber quais atendimentos ainda vão acontecer**. | F4 |
| HU04 | Como **atendente**, quero **cancelar um agendamento**, para **liberar o horário quando o cliente desistir**. | F1 |
| HU05 | Como **atendente**, quero **verificar se um horário está livre**, para **não marcar dois atendimentos juntos**. | F3 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar pet | O sistema deve cadastrar os animais atendidos pelo pet shop. | HU01 |
| RF02 | Cadastrar responsável | O sistema deve cadastrar os donos dos animais. | HU01 |
| RF03 | Marcar atendimento | O sistema deve registrar os agendamentos dos serviços. | HU02 |
| RF04 | Consultar horários | O sistema deve mostrar os agendamentos de uma data. | HU03 |
| RF05 | Cancelar agendamento | O sistema deve cancelar um agendamento existente. | HU04 |
| RF06 | Verificar horário | O sistema deve verificar se o horário escolhido está disponível. | HU05 |
| RF07 | Cadastrar serviço | O sistema deve cadastrar os serviços oferecidos pelo pet shop. | HU02 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade | O sistema deve ter informações simples e organizadas para facilitar o uso no balcão. | Características da 4.1 |
| RNF02 | Integridade | O sistema deve impedir agendamentos que entrem em conflito no mesmo horário. | F3 |
| RNF03 | Desempenho | O sistema deve mostrar os agendamentos de uma data em até 3 segundos em condições normais de uso. | Consulta rápida dos horários |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| Cadastrar os animais e seus donos. | RF01, RF02 |
| Cadastrar os serviços do pet shop. | RF07 |
| Marcar os atendimentos. | RF03 |
| Consultar os horários. | RF04 |
| Cancelar agendamentos. | RF05 |
| Evitar horários duplicados. | RF06, RNF02 |

Conferindo as tabelas, todas as histórias têm requisitos relacionados e todos os requisitos têm uma origem. Também foi verificado se as funções principais do PetAgenda aparecem no levantamento. Assim, o sistema fica focado em facilitar a rotina do balcão e ajudar a manter os horários organizados.
