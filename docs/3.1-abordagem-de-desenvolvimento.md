# 3.1 Abordagem de Desenvolvimento

O projeto segue uma abordagem **incremental**, em que o sistema será desenvolvido por partes. Primeiro serão produzidas as seções de descrição e análise do projeto, depois os requisitos e modelos, e por fim a implementação e os testes do sistema.

A abordagem aparece no PetAgenda através da criação e conferência das partes do sistema aos poucos. Ao final de cada etapa, a parte desenvolvida será conferida com as outras seções do projeto e a versão atualizada será colocada no repositório. Conforme o projeto avançar, as partes principais do sistema, como cadastro de pets, serviços e agendamentos, serão apresentadas ao cliente para verificar se atendem ao que foi solicitado.

Escolhemos essa abordagem porque permite fazer o projeto por etapas e corrigir problemas durante o desenvolvimento. No modelo cascata, as etapas seguem uma ordem mais rígida e alterações podem ser mais difíceis depois que uma etapa foi concluída. Também não vamos utilizar todas as práticas do Scrum, como sprints, reuniões diárias e uma equipe com papéis definidos, porque o projeto será desenvolvido como um trabalho escolar e não por uma equipe profissional utilizando Scrum.
